# Real-LLM Phase-0 results (H100, GSM8K)

**Setup.** Student = Qwen2.5-7B-Instruct (LoRA, transformers, H100). Verifier +
teacher = gpt-4o-mini (OpenAI, blinded to gold). GSM8K, 300-problem held-out eval,
512-example batches, 5 rounds. Corrective (train on teacher corrections of
rejects) vs frozen (no training). `results_real.json`, `exp_real_scissors.png`,
`run_h100.log`. Corrective run: 44.5 min on the H100.

## What it shows (Corollaries 1 & 2, on real LLMs)

1. **The blind spot is real and large with an INDEPENDENT verifier.** β = 0.41–0.56
   throughout — gpt-4o-mini (cross-family) accepts roughly half of the 7B's wrong
   answers on GSM8K.
2. **The blind spot scales with student capability.** β(round 0): 1.5B → 0.31,
   7B → 0.49. A stronger student makes subtler errors, so the verifier is fooled
   more — exactly the Corollary-1 mechanism.
3. **Dashboard blindness, empirically and starkly.** The dashboard reads a flat
   **~3% (range 0.027–0.040) across all 12 measurements**, while true user-facing
   error ranges **13% (frozen, healthy) to 32% (corrective, degrading)**. The
   in-loop dashboard is decoupled from reality: it cannot distinguish a stable good
   student from one the loop is actively wrecking. (`exp_real_scissors.png`)

## What it does NOT show — and why that's fine

Not the conservation-floor *scissors* (q falling while ε floors at q₀β₀). Real
cross-model fine-tuning **degrades** the 7B (q rises/thrashes: 0.25 → 0.50 → 0.42)
rather than smoothly improving it — training a strong model on ~110 gpt-4o-mini
solutions to hard problems at lr 2e-5 destabilises it (same direction as the Mac
1.5B run; bigger batches didn't fix it). The conservation floor is proven in the
**synthetic study + Appendix A**; the real run's job was to show the phenomenon is
real — and it does, arguably more vividly (a dashboard blind to *active
degradation*, not just to a floor).

## Track B — teacher-family axis (does the loop ever improve the student?)

1.5B student, verifier fixed = gpt-4o-mini, corrective loop, per-round raw error q:

| teacher | family | q trajectory (r0→r5) | outcome |
|---------|--------|----------------------|---------|
| gpt-4o-mini | cross | 0.32 → ~0.54 | degrades |
| gpt-4o | cross (verbose) | 0.32 → **1.00** (r1) | collapses (format break) |
| Qwen2.5-32B | **same** | 0.31 → 0.41 → 0.42 → 0.39 → **1.00** (r4) | degrades, then collapses |

**No teacher makes the loop improve the student.** The degradation is not a
teacher-family artifact; the corrective loop trains only on the verifier-rejected
(hardest) tail, which shifts the small student and, cumulatively, breaks its output
format (q→1.0). So the clean conservation *floor* is not reproducible on real LLMs at
this scale — it stays a theoretical result (synthetic + Appendix A). The robust
real-model story is dashboard blindness + the β-structure + this degradation.
Data: `results_teacher_gpt4o.json`, `results_teacher_32b.json`, `run_*.log`;
same-family teacher pre-generated by `pregen_teacher.py` (cached-teacher mode).

## Environment note

Bootstrapped bare Ubuntu 26.04 / H100: NVIDIA 580 (DKMS on kernel 7.0), micromamba
py3.11, torch 2.13+cu130. Stack quirks handled: Triton-compile EINTR (fixed by
`setsid` + clean-GPU launch), eager-attention numerical breakage (reverted to
SDPA), leftover-GPU-memory OOM on relaunch (wait for memory to free first).
Parallelised verifier/teacher API calls (24 threads) — the H100 is idle during
serial API otherwise.
